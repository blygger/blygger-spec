## What changed in the tool

The tool needed more changes than a new default path, and some of them affect the numbers:

- **Default spec** is `docs/protocol-v0.4.md`. You can still pass `--spec docs/protocol-v0.3.md`
  (checked: 193 clauses, no override warnings).
- **The near-match bug.** `ids.lock.json` keeps only the first 160 characters of each
  clause, and the near-match step compared that cut text with the full new sentence. So a
  long sentence edited near its end fell below 0.80 and lost its id. The new text is now
  cut to the same length before comparing. This keeps C-5.8-01, C-5.9-01, C-10.6-03,
  C-13.4-02 and C-15.2-01, which would otherwise have retired.
- **Version handling in `decisions.py`.** The living version is now a parameter
  (`--spec-version`; by default the version that `clauses.json` was extracted from). A
  reference into 0.2 or 0.3 counts as a spec reference, because #23 keeps section
  numbers from one version to the next. A 0.1 reference does not count. "§N at 0.1" is
  classified by the version named after it, so #22's "spec §11.4 at 0.1" is no longer a
  false stale reference.
- **The `reverses` relation.** The parser now reads "reverses" and "Reversed by", so it
  finds #79 → #32, from both records.
- **§10.3a crashed the section sort**, because it compared an int with a letter. Fixed in
  `analyze.py` and `extract.py`.
- **§16 statuses** now read every § that a "promoted to" heading names. #72 alone
  promotes 16.6e into §4, §5.8, §6.1, §12 and §15. A heading that says "no construct"
  now reads as closed. `overrides.json` can force a status with `pending_shapes`.
- **Decisions that cite a promoted §16 number.** These are now grounded where the text
  went. #63 used to read "pending §16 only" and now reads normative, through §16.6f →
  §5.6.
- **`clause_successors` in `overrides.json`.** This table maps retired ids to the ids that
  carry their rule now. A test that cites a retired id counts for its successor. The new
  `tests.retired-ids` check names each such test.

## (b) F13: rule sentences with no RFC 2119 keyword

**Source:** `analyze.py`'s two prose lints (`out/analysis.json` → `lowercase_modals`,
`absolutes`). They report 79 hits. One sentence (line 2163) appears in both lists, so there
are **78 distinct sentences**.

**What the labels mean (all of this is For Fable; nothing here edits the spec):**

- **R, restatement.** The same rule appears elsewhere with a keyword. The cited clause is
  that home. No action needed.
- **S, sole statement.** This is the only place the rule is stated, so it arguably needs a
  keyword. A suggested keyword is given.
- **N, not a rule.** Rationale, history, a description of the reference client, or a
  statement about the protocol's own design. A conforming party cannot fail it.

**Result:** R **40**, S **22**, N **16**. The 22 S sentences state **16 distinct rules**,
because six pairs say the same keyword-less rule twice. Compared with the "~56" in
`docs/fable-round-queue.md`: the 0.3 baseline had 63 hits, two of which gained their MUST
in session 38, and 0.4's new text added the rest.
