# v0.1 "Seed" — Implementation Plan

The publish-side client: a single-author Cloudflare Worker that composes/edits fragments in a private **studio** and publishes a conformant **page** at `/ygg`. No imports, no threads, no hoppers, no AI.

**For the implementing agent (Sonnet/Opus):** every protocol-shaped decision in this doc is already made — schemas, ID format, GUID strategy, tombstones, routes. Implement exactly what's written. If something is ambiguous or looks wrong, do not redesign: note it in `DEVLOG.md` open threads and flag it to Venkat. Local judgment calls (naming, code organization, error copy) are yours. Read `CLAUDE.md` first (session ritual, stack conventions).

## 1. Objective & non-goals

**Objective:** a deployed worker where the owner logs in, posts/edits/deletes fragments (with media), and the world sees a conformant `/ygg` page: human feed, RSS, manifest, canonical item files, permalinks. The feed must read normally in an ordinary RSS reader.

**Non-goals (v0.1):** subscriptions/imports, hoppers, threads, stubs, thumbs, filters, AI anything, RAG, custom themes, IPFS, multi-user. Don't build hooks for them either — the schemas below already leave room.

## 2. Protocol artifacts (build exactly these shapes)

### 2.1 IDs

- 128 random bits from `crypto.getRandomValues`, encoded as **26 chars of lowercase Crockford base32** (alphabet `0123456789abcdefghjkmnpqrstvwxyz`, no padding).
- Example: `7c9wk2mhq0v3xj8tn5rzfd41bg`
- IDs are permanent and identity; they never change on edit. Rationale (do not revisit): content hashes can't be identity because editing changes them; the hash below serves integrity/IPFS instead.

### 2.2 Content hash

`"sha256:" + hex(SHA-256(content_md as UTF-8))`, computed per published version.

### 2.3 Item JSON — `GET /ygg/items/{id}.json`

Ground truth for one item. Fragments in v0.1; `kind` values `thread` etc. arrive in later versions — readers must ignore unknown kinds (invariant 2).

```json
{
  "ygg": "0.1",
  "id": "7c9wk2mhq0v3xj8tn5rzfd41bg",
  "kind": "fragment",
  "origin": "https://example.com/ygg/",
  "author": { "name": "Venkatesh Rao", "url": "https://example.com/ygg/" },
  "created": "2026-07-17T18:00:00Z",
  "updated": "2026-07-18T09:30:00Z",
  "version": 3,
  "content_md": "Markdown source of the *latest* version.",
  "content_html": "<p>Markdown source of the <em>latest</em> version.</p>",
  "content_hash": "sha256:9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08",
  "media": [
    { "url": "media/x7f2.png", "mime": "image/png", "alt": "a diagram" }
  ],
  "changelog": [
    { "version": 1, "at": "2026-07-17T18:00:00Z", "note": null },
    { "version": 2, "at": "2026-07-17T21:12:00Z", "note": "typo" },
    { "version": 3, "at": "2026-07-18T09:30:00Z", "note": "sharpened the claim" }
  ]
}
```

Rules:
- Only the **latest** version's content is served (rolled-up presentation; changelog is metadata, not diffs). Older `content_md` is kept in the DB but not published in v0.1.
- All timestamps ISO 8601 UTC (`Z`). `version` is a positive integer, +1 per published save. Draft autosaves do not bump it.
- Media URLs are relative to `/ygg/`.
- **Tombstone:** deleting a published item keeps its file forever with `"kind": "tombstone"`, `version` bumped, `updated` set, `content_md`/`content_html` = `""`, `media` = `[]`, changelog retained plus a final entry. Rationale: subscribers (v0.2+) need a positive deletion signal; the spec is honest that remote copies survive.

### 2.4 Manifest — `GET /ygg/ygg.json`

```json
{
  "ygg": "0.1",
  "level": 1,
  "generator": "ygg-ref/0.1.0",
  "site": "https://example.com/ygg/",
  "title": "Venkat's ygg",
  "author": { "name": "Venkatesh Rao", "bio": "…", "avatar": "media/avatar.png", "links": [{ "label": "Home", "url": "https://venkateshrao.com" }] },
  "feed": "feed.xml",
  "items": "items/index.json",
  "updated": "2026-07-18T09:30:00Z"
}
```

### 2.5 Archive index — `GET /ygg/items/index.json`

Every published item + tombstone, no window. This is what makes lagging/new subscribers lossless.

```json
{
  "updated": "2026-07-18T09:30:00Z",
  "items": [
    { "id": "7c9wk2…", "kind": "fragment", "created": "…", "updated": "…", "version": 3 }
  ]
}
```

Ordered by `updated` descending.

### 2.6 Feed — `GET /ygg/feed.xml`

RSS 2.0 with a `ygg:` namespace. Namespace URI (see Open decisions): `https://github.com/vgururao/ygg/ns/0.1`.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<rss version="2.0" xmlns:ygg="https://github.com/vgururao/ygg/ns/0.1">
  <channel>
    <title>Venkat's ygg</title>
    <link>https://example.com/ygg/</link>
    <description>…author bio…</description>
    <lastBuildDate>Sat, 18 Jul 2026 09:30:00 GMT</lastBuildDate>
    <ygg:level>1</ygg:level>
    <ygg:manifest>https://example.com/ygg/ygg.json</ygg:manifest>
    <item>
      <guid isPermaLink="false">ygg:7c9wk2mhq0v3xj8tn5rzfd41bg:v3</guid>
      <link>https://example.com/ygg/f/7c9wk2mhq0v3xj8tn5rzfd41bg/</link>
      <title>Sharpened the claim — Markdown source of the latest…</title>
      <description><![CDATA[<p>rendered HTML of latest version</p>]]></description>
      <pubDate>Sat, 18 Jul 2026 09:30:00 GMT</pubDate>
      <ygg:id>7c9wk2mhq0v3xj8tn5rzfd41bg</ygg:id>
      <ygg:kind>fragment</ygg:kind>
      <ygg:version>3</ygg:version>
      <ygg:created>2026-07-17T18:00:00Z</ygg:created>
      <ygg:item>https://example.com/ygg/items/7c9wk2mhq0v3xj8tn5rzfd41bg.json</ygg:item>
    </item>
  </channel>
</rss>
```

Rules (decided, don't revisit):
- **GUID is per-version** (`ygg:{id}:v{n}`). Rationale: plain RSS readers dedupe by guid and would otherwise never resurface edits — per-version GUIDs make updates appear as new entries for L0 readers, which matches the "reverse-chron by latest update" philosophy. Ygg-aware readers (v0.2+) roll up by `ygg:id` instead and see no duplicates.
- One `<item>` per *published event*, newest first, window = latest **50** entries (an item edited twice recently may appear twice, at different versions; that's correct).
- `<title>`: edit note if present + first ~60 chars of plain-text content; tombstone events get title `deleted` and empty description.
- `<description>` HTML must be self-contained: absolute media URLs.
- `pubDate`/`lastBuildDate` in RFC 822 format; `ygg:*` timestamps stay ISO 8601.

### 2.7 Fragment constraint

`content_md` ≤ **1,000 characters** for fragments, enforced in studio at compose/edit time (protocol-level RECOMMENDED cap: 2,000 — enforcement is publisher-side only; readers must not reject long fragments).

## 3. Reference implementation architecture

**Stack:** TypeScript CF Worker, Hono for routing, `markdown-it` for rendering (safe mode: HTML in markdown escaped, not passed through), D1, R2. No client-side framework; server-rendered HTML + minimal vanilla JS. Repo layout: `worker/` (source), `worker/test/`, `wrangler.jsonc` at repo root or `worker/` — implementer's choice.

### 3.1 D1 schema

```sql
CREATE TABLE items (
  id TEXT PRIMARY KEY,
  kind TEXT NOT NULL DEFAULT 'fragment',       -- 'fragment' | 'tombstone'
  status TEXT NOT NULL DEFAULT 'draft',        -- 'draft' | 'public' | 'deleted'
  created TEXT NOT NULL,
  updated TEXT NOT NULL,
  version INTEGER NOT NULL DEFAULT 0,          -- last published version; 0 = never published
  content_md TEXT NOT NULL DEFAULT '',         -- working copy (may be ahead of last published)
  dirty INTEGER NOT NULL DEFAULT 0             -- working copy differs from last published version
);
CREATE TABLE versions (
  item_id TEXT NOT NULL,
  version INTEGER NOT NULL,
  content_md TEXT NOT NULL,
  content_hash TEXT NOT NULL,
  published_at TEXT NOT NULL,
  note TEXT,
  PRIMARY KEY (item_id, version)
);
CREATE TABLE media (
  id TEXT PRIMARY KEY,                          -- short random key, e.g. 8 chars same alphabet
  item_id TEXT,
  r2_key TEXT NOT NULL,
  mime TEXT NOT NULL,
  alt TEXT,
  created TEXT NOT NULL
);
CREATE TABLE settings ( key TEXT PRIMARY KEY, value TEXT NOT NULL );
-- settings keys: site_title, author_name, author_bio, author_links (JSON), site_url, avatar_media_id
```

Publish flow: bump `items.version`, insert `versions` row, set `dirty=0`, `updated=now`. Unpublish: `status='draft'` (item vanishes from all public surfaces including index — it was never deleted, just retracted; version history retained). Delete of a published item: `status='deleted'`, `kind='tombstone'`, version bump with empty content. Delete of a never-published draft: hard row delete.

### 3.2 Auth

Owner-only. `OWNER_PASSWORD` and `COOKIE_SECRET` as wrangler secrets. Login form POSTs password; on success set HttpOnly, Secure, SameSite=Lax cookie `ygg_session` = `expiry.hmacSHA256(expiry, COOKIE_SECRET)` (hex), 30-day expiry, constant-time comparison on verify. No users table, no OAuth. Register both secrets in `Code/.env.keys` per policy.

### 3.3 Routes

**Public (no auth, cache `public, max-age=60`):**

| Route | Serves |
|---|---|
| `GET /ygg/` | Feed page (HTML) |
| `GET /ygg/feed.xml` | §2.6 |
| `GET /ygg/ygg.json` | §2.4 |
| `GET /ygg/items/index.json` | §2.5 |
| `GET /ygg/items/{id}.json` | §2.3 (404 for drafts/unknown; tombstones 200) |
| `GET /ygg/f/{id}/` | Fragment permalink page (tombstone → page saying "deleted", 200) |
| `GET /ygg/media/{key}` | R2 object, long cache |

**Studio (cookie auth; unauthenticated → login):** `GET /studio` (feed + composer), `GET/POST /studio/login`, `POST /studio/logout`, `GET /studio/edit/{id}`, `GET /studio/settings`.

**API (cookie auth, JSON):** `POST /api/items` (create draft), `PUT /api/items/{id}` (save working copy), `POST /api/items/{id}/publish` (optional `note`), `POST /api/items/{id}/unpublish`, `DELETE /api/items/{id}`, `POST /api/media` (multipart; images only: png/jpg/gif/webp/svg, ≤ 5 MB), `PUT /api/settings`.

All public JSON/XML responses get permissive CORS (`Access-Control-Allow-Origin: *`) — other ygg clients will fetch them cross-origin in v0.2.

### 3.4 Rendering & pages

Everything rendered server-side from D1 on request (60s cache absorbs load; no materialization step). Public pages share one minimal stylesheet (`/ygg/style.css`): system font stack, readable measure (~65ch), no build step. Feed page shows published fragments newest-`updated` first, each with rendered HTML, `v{n} · {relative time}` line, permalink; edited items show `edited` + latest note. Only non-owner affordance: a visible RSS link/copy (per frozen spec clause: readers get nothing else). Pagination: single page of latest 100 + link to a plain `/ygg/archive/` page listing all items as title/date links.

### 3.5 Static export

`worker/scripts/export.ts` (run via `npm run export -- --out DIR --base https://example.com/ygg/`): fetches every public route and writes the file tree (§ "protocol on one screen" in README). Output must be byte-identical to what the worker serves (modulo none). This proves invariant 4 and is the v0.1 exit-criterion check for "servable from a dumb file host."
