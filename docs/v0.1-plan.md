## 1. Objective & non-goals

**Objective:** a deployed worker where the owner logs in, posts/edits/withdraws/pins fragments (with media), composes **threads** that transclude their own fragments, and the world sees a conformant `/ygg` page: human feed, RSS, manifest, canonical item files, permalinks, thread pages. The feed must read normally in an ordinary RSS reader — both kinds.

**Non-goals (v0.1):** subscriptions/imports, hoppers, stubs, thread-in-thread nesting, remote transclusion, thumbs, filters, AI anything, RAG, custom themes, IPFS, multi-user. Don't build hooks for them either — the schemas below already leave room.

## 2. Protocol artifacts (build exactly these shapes)

### 2.1 IDs

- 128 random bits from `crypto.getRandomValues`, encoded as **26 chars of lowercase Crockford base32** (alphabet `0123456789abcdefghjkmnpqrstvwxyz`, no padding).
- Example: `7c9wk2mhq0v3xj8tn5rzfd41bg`
- IDs are permanent and identity; they never change on edit. Rationale (do not revisit): content hashes can't be identity because editing changes them; the hash below serves integrity/IPFS instead.

### 2.2 Content hash

`"sha256:" + hex(SHA-256(content_md as UTF-8))`, computed per published version.

### 2.3 Item JSON — `GET /ygg/items/{id}.json`

Ground truth for one item. Fragments **and threads** in v0.1 (session-3 restructure); further `kind` values arrive in later versions — readers must ignore unknown kinds (invariant 2). Thread items additionally carry a `transclusions` provenance array (§2.9); the example below is a fragment.

```json
{
  "ygg": "0.1",
  "id": "7c9wk2mhq0v3xj8tn5rzfd41bg",
  "kind": "fragment",
  "origin": "https://example.com/ygg/",
  "author": { "name": "Venkatesh Rao", "url": "https://example.com/ygg/" },
  "created": "2026-07-17T18:00:00Z",
  "updated": "2026-07-18T09:30:00Z",
  "version": 3,
  "content_md": "Markdown source of the *latest* version.",
  "content_html": "<p>Markdown source of the <em>latest</em> version.</p>",
  "content_hash": "sha256:9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08",
  "media": [
    { "url": "media/x7f2.png", "mime": "image/png", "alt": "a diagram" }
  ],
  "changelog": [
    { "version": 1, "at": "2026-07-17T18:00:00Z", "note": null },
    { "version": 2, "at": "2026-07-17T21:12:00Z", "note": "typo" },
    { "version": 3, "at": "2026-07-18T09:30:00Z", "note": "sharpened the claim" }
  ]
}
```

Rules:
- Only the **latest** version's content is served (rolled-up presentation; changelog is metadata, not diffs). Older `content_md` is kept in the DB and not published — **unless the author pins a version** (§2.8), which exposes exactly that version, permanently.
- All timestamps ISO 8601 UTC (`Z`). `version` is a positive integer, +1 per published save. Draft autosaves do not bump it.
- Media URLs are relative to `/ygg/`.
- **Withdrawn** (session-3 revision; replaces both the tombstone and the silent unpublish-to-404): withdrawing a published item publishes a permanent **endcap** — version bump with `content_md`/`content_html` = `""`, `media` = `[]`, optional note, `"kind": "withdrawn"`, `updated` set, changelog retained plus the endcap entry. The item file stays **200 forever**. Compliant subscribers roll the item up to null and drop it from their local archive; the spec stays honest that remote copies survive and that pinned versions (§2.8) remain fetchable. Withdrawal is **reversible**: a later publish event (vN+1, `"kind": "fragment"`) is the item returning, and clients that dropped it simply re-import it. There is no separate "delete" of a published item — no permanent-delete state exists in the protocol. Discarding a never-published draft is a hard delete (nothing was ever public).
- Changelog entries carry an optional `"pinned": true` when that version is pinned (§2.8); absent means unpinned.
- **Reserved for v0.3 (do not emit in v0.1):** optional top-level `"forked_from": { "id": "...", "version": N }` — lineage pointer for an item that continues from a **pinned** version of another item. It MUST reference a pinned version. Defined now so pin design accounts for it; implementation arrives with threads.

### 2.4 Manifest — `GET /ygg/ygg.json`

```json
{
  "ygg": "0.1",
  "level": 1,
  "generator": "ygg-ref/0.1.0",
  "site": "https://example.com/ygg/",
  "title": "Venkat's ygg",
  "author": { "name": "Venkatesh Rao", "bio": "…", "avatar": "media/avatar.png", "links": [{ "label": "Home", "url": "https://venkateshrao.com" }] },
  "feed": "feed.xml",
  "items": "items/index.json",
  "updated": "2026-07-18T09:30:00Z"
}
```

### 2.5 Archive index — `GET /ygg/items/index.json`

Every published item + tombstone, no window. This is what makes lagging/new subscribers lossless.

```json
{
  "updated": "2026-07-18T09:30:00Z",
  "items": [
    { "id": "7c9wk2…", "kind": "fragment", "created": "…", "updated": "…", "version": 3 }
  ]
}
```

Ordered by `updated` descending.

### 2.6 Feed — `GET /ygg/feed.xml`

RSS 2.0 with a `ygg:` namespace. Namespace URI (see Open decisions): `https://github.com/vgururao/ygg/ns/0.1`.

```xml
<?xml version="1.0" encoding="UTF-8"?>
<rss version="2.0" xmlns:ygg="https://github.com/vgururao/ygg/ns/0.1">
  <channel>
    <title>Venkat's ygg</title>
    <link>https://example.com/ygg/</link>
    <description>…author bio…</description>
    <lastBuildDate>Sat, 18 Jul 2026 09:30:00 GMT</lastBuildDate>
    <ygg:level>1</ygg:level>
    <ygg:manifest>https://example.com/ygg/ygg.json</ygg:manifest>
    <item>
      <guid isPermaLink="false">ygg:7c9wk2mhq0v3xj8tn5rzfd41bg:v3</guid>
      <link>https://example.com/ygg/f/7c9wk2mhq0v3xj8tn5rzfd41bg/</link>
      <title>Sharpened the claim — Markdown source of the latest…</title>
      <description><![CDATA[<p>rendered HTML of latest version</p>]]></description>
      <pubDate>Sat, 18 Jul 2026 09:30:00 GMT</pubDate>
      <ygg:id>7c9wk2mhq0v3xj8tn5rzfd41bg</ygg:id>
      <ygg:kind>fragment</ygg:kind>
      <ygg:version>3</ygg:version>
      <ygg:created>2026-07-17T18:00:00Z</ygg:created>
      <ygg:item>https://example.com/ygg/items/7c9wk2mhq0v3xj8tn5rzfd41bg.json</ygg:item>
    </item>
  </channel>
</rss>
```

Rules (decided, don't revisit):
- **GUID is per-version** (`ygg:{id}:v{n}`). Rationale: plain RSS readers dedupe by guid and would otherwise never resurface edits — per-version GUIDs make updates appear as new entries for L0 readers, which matches the "reverse-chron by latest update" philosophy. Ygg-aware readers (v0.2+) roll up by `ygg:id` instead and see no duplicates.
- One `<item>` per *published event*, newest first, window = latest **50** entries (an item edited twice recently may appear twice, at different versions; that's correct).
- `<title>`: edit note if present + first ~60 chars of plain-text content; withdrawal events get title `withdrawn` and empty description.
- A withdrawn item contributes exactly one feed entry (its withdrawal event); earlier publish events drop from the window (DEVLOG session 2 interpretation, carried over from tombstones). Pinning emits **no** feed event — it is a promise change, not a content change; the changelog `pinned` flag is the signal.
- `<description>` HTML must be self-contained: absolute media URLs.
- `pubDate`/`lastBuildDate` in RFC 822 format; `ygg:*` timestamps stay ISO 8601.

### 2.7 Fragment constraint

`content_md` ≤ **1,000 characters** for fragments, enforced in studio at compose/edit time (protocol-level RECOMMENDED cap: 2,000 — enforcement is publisher-side only; readers must not reject long fragments).

### 2.8 Pinned version file — `GET /ygg/items/{id}/v{n}.json` (session-3 addition)

A **pin** is the author's irrevocable hosting promise for one specific published version: "this exact content stays fetchable at this URL forever" — surviving later edits *and* withdrawal of the item's live stream. Only pinned versions get per-version files; unpinned history stays withheld (this is what keeps withdrawal meaningful and preserves the author's default mutability). Analogy (recorded in the proposal doc): the item id plays the IPNS-name role (mutable pointer), a pinned version plays the CID role (immutable, citable) — ygg inverts IPFS's default because it is an authoring medium: mutable by default, immutable by explicit act.

```json
{
  "ygg": "0.1",
  "id": "7c9wk2mhq0v3xj8tn5rzfd41bg",
  "kind": "fragment",
  "version": 2,
  "at": "2026-07-17T21:12:00Z",
  "note": "typo",
  "pinned": true,
  "origin": "https://example.com/ygg/",
  "author": { "name": "Venkatesh Rao", "url": "https://example.com/ygg/" },
  "content_md": "…that version's markdown…",
  "content_html": "<p>…that version's HTML…</p>",
  "content_hash": "sha256:…"
}
```

Rules:
- 404 for unpinned versions and unknown ids. 200 forever once pinned — including after withdrawal of the item.
- Pinning is **irrevocable**. Any published version with content may be pinned, including past versions (retroactively exposing withheld history is the author's right). Endcap (withdrawal) versions cannot be pinned — there is nothing to cite.
- No `media` array: media objects are immutable once uploaded and served with immutable cache headers from `/ygg/media/`; the pinned `content_html` references them absolutely or relative to `/ygg/`. Consequence: **media referenced by any pinned version must be retained forever.**
- Pinning does not freeze the id. The live stream continues (vN+1…) under the same identity; the pin guarantees only the citation. Forking from a pin (new id + `forked_from`) is specced in §2.3 and lands in v0.3.
- Threads are pinnable like fragments; a pinned thread version serves its publish-time `content_html` (baked transclusion snapshots included) and its `transclusions` provenance, with `"kind": "thread"`.

### 2.9 Threads & transclusion (session-3 addition — grammar is permanent protocol surface)

A thread is an item with `"kind": "thread"`: long-form markdown that **transcludes** the author's own fragments. Same identity, versioning, changelog, withdraw, and pin machinery as fragments. v0.1 threads are local-only: no imported sources, no stubs.

**Grammar (locked, session 3 — do not modify without Fable + Venkat):**

- A line consisting solely of `![[` + a 26-char item id + `]]` (surrounding whitespace allowed) is a **transclusion directive**. Example: `![[7c9wk2mhq0v3xj8tn5rzfd41bg]]`
- Anywhere else — inline, inside code blocks — the same character sequence is inert text.
- `![[id@vN]]` (explicit version) is **reserved**: v0.1 publishers must reject it; readers must tolerate it as an unknown construct (invariant 2).

**Publish-time resolution (studio-side; readers never resolve anything):**

- Every directive must resolve to a **local, currently-published, `kind: "fragment"`** item. Drafts, withdrawn items, unknown ids, and threads (no nesting until v0.3) are errors: publish fails listing the bad references.
- Resolution **snapshots** the target's latest published version: its rendered HTML is baked into the thread's `content_html` wrapped as
  `<blockquote class="ygg-transclusion" data-ygg-id="{id}" data-ygg-version="{n}">…fragment html…</blockquote>`
  and `{ "id": …, "version": … }` is appended (in directive order) to the thread's top-level `"transclusions"` array in item JSON. `content_md` keeps the directives — it is the authoring source of truth.
- Republishing a thread re-resolves every directive to the then-latest versions (snapshot-at-publish). Staleness detection/regeneration is v0.4; in v0.1 the author republishes manually.

**Snapshot independence (the rule that makes v0.3 network cycles harmless, applied locally first):**

- Later edits, withdrawal, or pinning of a source fragment do **not** touch the thread's baked snapshot. Withdrawal does not cascade — content published into a thread stays in the thread, same honesty rule as remote caches.
- **No auto-pin** (locked, session 3): `transclusions[].version` is provenance metadata and may name a version with no fetchable per-version file. Pinning stays a separate deliberate act; the self-contained baked HTML carries the content.

**Other thread rules:** no fragment length cap (threads are long-form; no protocol cap); media attachments allowed as on fragments; a **withdrawn** thread's endcap empties `transclusions` to `[]` alongside `content_md`/`content_html`/`media`; feed entries for threads carry the full baked self-contained HTML (automatic given the snapshot rule).

## 3. Reference implementation architecture

**Stack:** TypeScript CF Worker, Hono for routing, `markdown-it` for rendering (safe mode: HTML in markdown escaped, not passed through), D1, R2. No client-side framework; server-rendered HTML + minimal vanilla JS. Repo layout: `worker/` (source), `worker/test/`, `wrangler.jsonc` at repo root or `worker/` — implementer's choice.

### 3.1 D1 schema

```sql
CREATE TABLE items (
  id TEXT PRIMARY KEY,
  kind TEXT NOT NULL DEFAULT 'fragment',       -- 'fragment' | 'thread' | 'withdrawn'
  status TEXT NOT NULL DEFAULT 'draft',        -- 'draft' | 'public' | 'withdrawn'
  created TEXT NOT NULL,
  updated TEXT NOT NULL,
  version INTEGER NOT NULL DEFAULT 0,          -- last published version; 0 = never published
  content_md TEXT NOT NULL DEFAULT '',         -- working copy (may be ahead of last published)
  dirty INTEGER NOT NULL DEFAULT 0             -- working copy differs from last published version
);
CREATE TABLE versions (
  item_id TEXT NOT NULL,
  version INTEGER NOT NULL,
  content_md TEXT NOT NULL,
  content_html TEXT NOT NULL DEFAULT '',       -- publish-time rendering; for threads this holds the baked transclusion snapshots (migration 0003)
  content_hash TEXT NOT NULL,
  published_at TEXT NOT NULL,
  note TEXT,
  transclusions TEXT,                          -- JSON [{id,version}] for threads; NULL for fragments (migration 0003)
  pinned INTEGER NOT NULL DEFAULT 0,           -- 1 = irrevocably pinned (§2.8)
  pinned_at TEXT,
  PRIMARY KEY (item_id, version)
);
CREATE TABLE media (
  id TEXT PRIMARY KEY,                          -- short random key, e.g. 8 chars same alphabet
  item_id TEXT,
  r2_key TEXT NOT NULL,
  mime TEXT NOT NULL,
  alt TEXT,
  created TEXT NOT NULL
);
CREATE TABLE settings ( key TEXT PRIMARY KEY, value TEXT NOT NULL );
-- settings keys: site_title, author_name, author_bio, author_links (JSON), site_url, avatar_media_id
```

Publish flow: bump `items.version`, insert `versions` row (with publish-time `content_html`; for threads, resolve every `![[id]]` directive per §2.9 first — failures abort with the bad-reference list — and store the provenance JSON in `versions.transclusions`), set `dirty=0`, `updated=now`. Republishing a withdrawn item is the same flow (it also restores `status='public'` and the item's authored kind, derived from the latest non-endcap version: `transclusions` NULL → `'fragment'`, else `'thread'`). **Withdraw** (session-3 revision — the only way a published item leaves the public stream): `status='withdrawn'`, `kind='withdrawn'`, version bump with an empty-content endcap row (optional note); the working copy `content_md` is **retained** (withdrawal governs the public surface, not the studio) and `dirty=1` (the working copy now differs from the published endcap). **Pin**: set `versions.pinned=1`, `pinned_at=now` — never unset. Discard of a never-published draft: hard row delete. There is no delete of a published item.

### 3.2 Auth

Owner-only. `OWNER_PASSWORD` and `COOKIE_SECRET` as wrangler secrets. Login form POSTs password; on success set HttpOnly, Secure, SameSite=Lax cookie `ygg_session` = `expiry.hmacSHA256(expiry, COOKIE_SECRET)` (hex), 30-day expiry, constant-time comparison on verify. No users table, no OAuth. Register both secrets in `Code/.env.keys` per policy.

### 3.3 Routes

**Public (no auth, cache `public, max-age=60`):**

| Route | Serves |
|---|---|
| `GET /ygg/` | Feed page (HTML) |
| `GET /ygg/feed.xml` | §2.6 |
| `GET /ygg/ygg.json` | §2.4 |
| `GET /ygg/items/index.json` | §2.5 |
| `GET /ygg/items/{id}.json` | §2.3 (404 for drafts/unknown; withdrawn 200 forever) |
| `GET /ygg/items/{id}/v{n}.json` | §2.8 pinned version file (404 unless pinned; 200 forever once pinned, survives withdrawal) |
| `GET /ygg/f/{id}/` | Fragment permalink page (withdrawn → page saying "withdrawn", 200) |
| `GET /ygg/t/{id}/` | Thread page (§2.9): full baked HTML with provenance links; withdrawn → "withdrawn" page, 200 |
| `GET /ygg/media/{key}` | R2 object, long cache (immutable; retained forever if referenced by a pinned version) |

**Studio (cookie auth; unauthenticated → login):** `GET /studio` (feed + composer), `GET/POST /studio/login`, `POST /studio/logout`, `GET /studio/edit/{id}`, `GET /studio/settings`.

**API (cookie auth, JSON):** `POST /api/items` (create draft; optional `kind: "fragment" | "thread"`, default fragment), `PUT /api/items/{id}` (save working copy; allowed for withdrawn items — editing toward republish), `POST /api/items/{id}/publish` (optional `note`; also the republish path for withdrawn items), `POST /api/items/{id}/withdraw` (optional `note`; published items only), `POST /api/items/{id}/pin` (body `{version}`; irrevocable, endcap versions rejected, idempotent), `DELETE /api/items/{id}` (never-published drafts only — published items are withdrawn, not deleted), `POST /api/media` (multipart; images only: png/jpg/gif/webp/svg, ≤ 5 MB), `PUT /api/settings`.

All public JSON/XML responses get permissive CORS (`Access-Control-Allow-Origin: *`) — other ygg clients will fetch them cross-origin in v0.2.

### 3.4 Rendering & pages

Everything rendered server-side from D1 on request (60s cache absorbs load; no materialization step). Public pages share one minimal stylesheet (`/ygg/style.css`): system font stack, readable measure (~65ch), no build step. Feed page shows published items newest-`updated` first — fragments inline in full; **threads as an excerpt card** (~300 chars of plain text + "read the thread →" link to `t/{id}/`; presentation choice, not protocol — feed.xml always carries the full thread HTML). Each item: rendered HTML, `v{n} · {relative time}` line, permalink; edited items show `edited` + latest note. Thread pages render baked transclusions with their `ygg-transclusion` styling and a small provenance link per block (`f/{id}/`). Only non-owner affordance: a visible RSS link/copy (per frozen spec clause: readers get nothing else). Pagination: single page of latest 100 + link to a plain `/ygg/archive/` page listing all items as title/date links.

### 3.5 Static export

`worker/scripts/export.ts` (run via `npm run export -- --out DIR --base https://example.com/ygg/`): fetches every public route and writes the file tree (§ "protocol on one screen" in README). Output must be byte-identical to what the worker serves (modulo none). This proves invariant 4 and is the v0.1 exit-criterion check for "servable from a dumb file host."
